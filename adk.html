Building an agent that behaves: the Agent Development Kit, end to end

ADK is the code-first way to build an agent: you write Python, it handles the orchestration. Most of what goes wrong is invisible in the code, a docstring that decides whether a tool is ever chosen, a state key renamed in one place that silently breaks three others, a callback that short-circuits everything downstream, model-written code running where it can do damage. Ten sections, each with the plain-English version first, and simulations for the parts that only make sense once you have seen them fail.

The machine behind this lab: a tool rack that reads its tags

In plain English: an agent picks a tool by reading each tool’s description, the way this carriage reads the tag hanging on every tool. A clear tag and the right tool lifts off its hook. Two look-alike pliers carry blank tags, and on the request that needs one of them the carriage cannot choose. That is the lab’s first lesson: when the wrong tool is picked, fix the description before blaming the model.
