Study activity

Three tracks. They are independent (start whichever suits you) but the order within each is deliberate, and each lab still stands on its own if you would rather not follow it. New to all of it? Open Cloud lab for foundations, or ADK lab to build something today. Revising? The cheatsheet puts every lab’s must-remember points on one printable page.

Build, run and govern an agent: 9 labs, in order

The main track, and the one most people want. Build one, run it in production, hand the building to a coding agent, measure it, secure it, publish it, then the capstone carries a single agent through every stage at once.

1 Google Cloud ADK lab Build a working agent, give it tools, and understand why it picks the ones it does. 10 tabs · 11 simulations · first agent to production routing
2 Pick your frame Build the same agent five ways, see what each framework's opinion costs, and untangle the Lang-family names. 9 tabs · 11 simulations · one loop, five philosophies
3 AWS AgentCore lab Take an agent that works on your laptop and make it one you would trust in production. 9 tabs · 10 simulations · scenario drill
4 Google Cloud Agents building agents Write a specification precise enough that a coding agent builds the right thing from it. 9 tabs · 10 simulations · spec to running service
5 Google Cloud Evaluation & hill climbing Answer “did that change make it better?” with a number instead of an opinion. 11 tabs · 14 simulations · metrics to unit economics
6 AWS Azure Google Cloud The number to trust Pick the metric that fits the mistake, and defend a threshold with named stakes. 11 tabs · 14 simulations · one class of twenty throughout
7 Google Cloud Govern & secure agents Decide what an agent is allowed to do, and stop it doing everything else. 12 tabs · 13 simulations · gateway to audit trail
8 Google Cloud Gemini Enterprise rollout Put an agent in front of a whole company without breaking identity, search or trust. 12 tabs · 14 simulations · identity to rollout
9 Google Cloud Peak Week, one agent end to end Carry one agent through all six stages in a single sitting, and see where each one bites. 10 tabs · 16 simulations · groundwork → work → survive → safe → good → theirs

Cloud and architecture: 4 labs, in order

How the cloud actually works, how to draw it so somebody else can act on it, and then the two exam workbenches. Useful on its own, and the ground the agent track is standing on.

1 AWS Azure Google Cloud Cloud lab Follow one request from a phone to a database and name every box it passes through. 14 tabs · 27 diagrams · 30 simulations · 94 services mapped
2 AWS Azure Google Cloud Architecture diagrams Draw a diagram that survives a review and tells people what to do. 11 tabs · 11 simulations · a synthesis you may argue with
3 Google Cloud GCP Architect exam Read a case study the way the exam does, and find the clause that rules the others out. case workbench · 4 simulations
4 AWS SAP-C02 cheatsheet Hear a phrase in a question and know immediately what it is really asking for. trigger drill · decision tables

Under the hood: 6 labs, in order

The layers everything above is running on. Optional depth rather than a prerequisite, take it whenever you want to know why inference is priced the way it is, and read it in order.

1 AWS Azure Google Cloud The machine underneath Understand why an expensive card spends most of its time waiting, and what to do about it. 10 tabs · 13 simulations · worked on a named machine
2 AWS Azure Google Cloud Wrong, then less wrong Watch a network actually train, live in the page, until a decision boundary appears. 8 tabs · 11 simulations · the networks train in your browser
3 AWS Azure Google Cloud Before the network Meet the four little machines behind most real decisions, and learn which one to reach for. 8 tabs · 8 simulations · one classroom, four machines
4 AWS Azure Google Cloud One token at a time See exactly what happens between your prompt and the answer, one token at a time. 12 tabs · 25 simulations · arithmetic on named models
5 AWS Azure Google Cloud The engine, not the model Understand what an inference engine does that the model itself does not. 13 tabs · 16 simulations · systems, not modelling
6 AWS Azure Google Cloud Twenty engines, one endpoint Put twenty engines behind one endpoint and decide which of them gets each request. 9 tabs · 9 simulations · above the engine
